Version 0.2 of the design system exists and its screens work. It was built overnight on the Instrument direction, got one fresh review, failed it, and was fixed. The fixes have not been reviewed again.

## Three decisions for you

1. **Blue or teal.** Both are built; one token switches them. The lead recommends blue: teal sits 45 degrees of hue from the green used for "success", and blue sits 108 or more from every status colour. Pictures are below. *Default until you say: blue.*
2. **Which framework Souvenir's products use.** Version 0.2 is plain HTML and CSS with three small web components, so it runs anywhere. If your products are React, Vue or another framework, say which, and wrappers come next. *Default: none; plain HTML and web components.*
3. **UI SDK or the 5 kilobyte budget: it cannot be both.** You approved UI SDK for shipped components. Built and measured, its button is 15.6 kilobytes, checkbox 19.2, field 22.4, select 63.3, against the row of 5 per component. Our own scripts for the same jobs are 0.7 to 1.2. For these four parts UI SDK adds a select with a keyboard popup and little else a checkout needs (`explore/ui-sdk-trial/README.md`). *Default taken: no shipped part uses UI SDK.* To use it, name the new budget row. It is still the candidate for the parts plain HTML cannot do: date picker, combobox, and letting an agent operate a page.

## What failed

- **The one review failed version 0.2.** Three fresh reviewers returned 4 blockers, 34 major and 24 minor findings (`gates/raw/2026-11-15-final-review.json`). The fixes are in `gates/raw/2026-11-15-review-fixes.json`. The fixes were checked by scripts and by the lead, and were not reviewed again, because you asked for one review.
- **The worst fault was the lead's own.** A late patch made "Apply code" a second submit button in the paying form. Pressing Enter in any field then pressed "Apply code" and wiped everything typed. It is fixed (the code is a form of its own), the lead confirmed with a script that Enter now pays, and a lint rule and a check now guard it.
- **A turning "Checking both calendars…" sat above the finished answer** on both assistant screens: faked progress. Removed, and a check now forbids it.
- **Text at 200 percent spilled out of the cost display and the error summary.** Fixed; every screen is now also checked at 200 percent.
- **The checks are weaker than they look.** A reviewer wrote sixteen deliberately bad pages and eleven passed. Nine more lint rules were added for the commonest; passing the checks still does not prove a screen is right.
- **A reviewer's stray file and five missing built files got into one commit** because the lead staged everything while reviewers were running. Corrected in the next commit.

## Not done

- **UI SDK is in no shipped part** (decision 3).
- **The cost summary sits in the core,** and your rule is that nothing ecommerce-only may. It needs a separate commerce layer. Not moved tonight.
- **No increased-contrast theme.** Light and dark only.
- **No radio buttons, tabs, dialog, table, date picker or navigation.** AGENTS.md lists them as missing.
- **Theme and accent are lost when a form is submitted** on these static pages, and "Apply code" reloads the page because there is no server behind it.
- **The delete-confirmation page uses the same blue button as Pay.** A reviewer thinks the colour invites the irreversible choice. Left for a test with people.
- **Nothing was tested with people, a screen reader, a real phone, or any browser but Chromium.**
- **Gate 1 and Gate 2 were not run,** as you instructed for tonight. Version 0.2 has not been released to anyone.
