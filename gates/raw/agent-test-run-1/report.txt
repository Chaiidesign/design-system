**3. Hesitations and guesses**
- **Status and total on one row.** layout.md says `sv-list__trail` holds "an amount, a `sv-status` or a quiet button". That reads as one thing, and I needed an amount and a status on each order. I put the amount in the trail (rule 10 names the trail for amounts) and the status in a detail line. The docs never say a status may sit in `sv-list__detail`. The lint accepted it, but I guessed.
- **Fix-payment control.** I wasn't sure whether to use a quiet or secondary button, or a link. layout.md says the trail may hold a quiet button, but the trail was taken by the amount.
  - I used `a.sv-button` because it goes to another page, and AGENTS.md rule 6 says a link is an `<a>`.
  - I chose secondary because quiet looks like a plain link. The brief says the failed order needs a way to fix it, so I wanted it to stand out.
  - I put it in `sv-list__main`, which is an undocumented placement.
- **Where the delete form goes.** There is no dialog, and no doc covers destructive actions.
  - I used a separate form on a panel with a warning message.
  - I made the button secondary, because AGENTS.md rule 4 says only the action that commits is primary, and Save already took it.
  - I'm unsure whether "delete" counts as a commit.
  - The button label is "Delete account", which fits the "says what it does and to what" rule. No confirmation step exists, so one click deletes.
- **Group label for the checkboxes.** checkbox.md shows `role="group" aria-label="..."`. I used `aria-labelledby` pointing at the visible `h2` "Notifications" instead, so the label is visible (rule 7). Whether `aria-labelledby` is allowed on the group is not stated. The lint passed it.
- **Nested h2.** The `h2` sits in a `section` that carries the same `aria-labelledby`, and the group points at that same `h2`. That works, but it is redundant.
- **Hints.** field.md says a hint is "one sentence, no full stop". I gave the email a hint and left the name and language without one, since a hint is optional.
- **Select with no empty option.** select.md says a required select starts on an empty option. Language always has a value, so I didn't make it required and preselected English. The "Don't" in select.md is about required choices, so I think this is fine. The docs don't cover a select with a sensible default.
- **Language names.** I didn't put `lang` attributes on the Français, Deutsch and 日本語 options. That is good practice, but the docs don't mention it, and AGENTS.md says never to invent. I did not test whether the lint allows it.
- **Cancelled tone.** The status table has no "cancelled" example. I chose `warning`. `danger` is for failure, and `info` seemed too quiet for something the person may not have wanted.
- **Being prepared tone.** `busy` says "something is in progress". Its example label ends in "…" and the table shows a spinning ring. I wasn't sure it suits a state that lasts days, and I left off `role="status"`. Another option was `info`.
- **Order of orders.** The brief gave no order. I listed newest first and mixed the states.
- **Dates.** I wrote "12 November" with no year, per the Words section. Orders from the previous year would be ambiguous, but the docs only give that format.
- **The "·" separator** between date and item count is plain text. I assume it is allowed.
- **Empty and error links.** Empty has a "Start shopping" link to `/shop`, an invented URL. Error has a "Try again" link to orders.html, because a `button type="button"` does nothing without script. message.md's example uses a button, which would break rule 6 on this page.
- **Wording of the error message.** AGENTS.md gives "We couldn't load your orders", and I wrote "could not" instead. "couldn't" is a contraction, and I wasn't sure of the house style. I also added "you have not been charged", which is a claim I can't know on a page that only lists orders.
- **Page title.** The skeleton uses a `<title>` matching the `h1`. I gave all three orders pages the same title, "Your orders", with no state in it.
