3. HESITATIONS AND GUESSES
- **Language: heading or label?** I first wrote an h2 "Language" over a field labelled "Language", which repeated itself in the screenshot. I moved the select into "Your details" and dropped the extra heading. The docs don't say whether a lone field needs a section heading.
- **Should the settings form use the error summary?** error-summary.md says it lists "every field's error" after a failed submit, so I included it, hidden. Nothing says whether it is required on a two-field form, or how a server-rendered settings page should show a failed save.
- **`data-user-content` (rule 9).** The name and email values are words a person typed. They sit in input values, where an attribute on an element makes no sense. I did not add the attribute. The rule doesn't say whether it applies to values shown in inputs, or to the name if it were displayed as text.
- **Hint wording.** I wrote "We'll send order updates here" with no full stop, per field.md. The name field has no hint because it needed none.
- **Which order is "the failed one", and where it sits.** The docs say nothing on ordering. I sorted newest first and put the failed order third.
- **Order links.** Titles link to `/orders/10431` style paths that don't exist, as in the layout.md example. I used a relative `delete-account.html` link for the delete flow so it works from the file system. This is inconsistent, and the docs don't say which style to use for screens.
- **Cancelled status.** status.md says cancelled is `info`. That was clear and I followed it.
- **Notification labels.** checkbox.md says a label states what checking it means. I chose "Email me updates about my orders", "Text me updates about my orders" and "Email me news and offers". The docs have no wording rule for opt-in marketing boxes beyond "never a box ticked for the person" (I left it unticked).
- **Delete section wording.** I added a short explanatory paragraph in the settings page's delete section ("Deleting your account removes your details and your order history. It cannot be undone."). patterns.md only shows the link, not whether to add text beside it. The paragraph is bare text in a stack, which I assumed was allowed.
- **Delete page.** The list of what is lost ("name, email address, notification choices, record of orders") is invented. The docs show a different example list, so I couldn't tell how literal to be.
- **Title tags.** The skeleton shows `<title>Checkout</title>`. I used the page's h1 text. The docs don't say how titles should differ across the states of the same page. orders-empty and orders-error share the title "Your orders".
- **Error wording on the failed-load page.** I first added "Try again in a moment." beside the Try again link. It repeated the link, so I removed it.
