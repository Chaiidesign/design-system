# UI SDK: what it is and what it costs

Source summary, 14 November 2026. Clay: research for a decision, not a spec. The decision made from it is DECISIONS.md D-013 and A-16.

The CEO wrote "we need to use this" about https://ui-sdk.dev on 14 November. This file records what was read, what was measured, and what the docs do not say.

## How it was read

- **What was fetched:** the site's ten text files for agents, about 920 kilobytes, on 14 November 2026. Their checksums are in `raw/2026-11-14-ui-sdk-docs-sha256.txt`.
- **What was read in full:** six of the ten: `llms.txt`, the Core, Agents and Guides files, the Web Components file and `web.md`. The React file was read only for its component list. The Vue, Svelte and Solid files were not read; a reviewer later counted their component lists (55 each, the same names).
- **Who read it:** six Opus readers took one range each and a seventh looked up the public registry and repository. Each fact had to carry a file, a line number and an exact quote. Their full returns are in `raw/2026-11-14-ui-sdk-and-skills-readers.json`.
- **How it was checked:** a script searched for every quote. 232 of the 233 quotes from the docs files were found within three lines of the stated line; the one miss is a quote the reader mistyped ("prefer" for "prefers", `core:6180`). The output is `raw/2026-11-14-ui-sdk-quote-check.txt`. The lead re-fetched the registry and repository facts marked "lead re-checked". A fresh reviewer then opened all 47 line references in the first draft of this file, searched for each thing said to be missing, and re-fetched the registry; its 13 corrections are applied here.
- **What was not read:** the per-component pages (Button, Field, Input, Toast, Time Input and the rest); the server-rendering and styling pages for React, Vue, Svelte and Solid; the changelogs of the five adapters; the contents of `web.css` and of the stylesheet UI SDK injects; and the source code. ## What it is

UI SDK is a library of interface behaviours: focus, keyboard navigation, selection, popups, dragging, and the accessibility attributes those need (`core:14`). You describe a component once as a "primitive" (its state, its actions and its named parts), and an adapter renders it in React, Vue, Svelte, Solid or as web components (`core:38`, `core:40`). It also ships 55 ready-made components, the same list in every framework. The list includes Button, Field, Input, Label, Checkbox, Select, Dialog, Toast, Progress, Calendar, Date Picker, Time Input, Textarea and Scroll Area.

It has a second half: a way for an AI agent to read and operate the components on a live page (`agents:5`). Of the three behaviour libraries in our survey, it is the only one with this.

## Facts that help us

- **It brings no look.** Parts render unstyled (`core:42`). Styling hooks are a `data-slot` attribute naming each part, `data-*` and ARIA attributes for state, and CSS variables for values (`core:882`, `core:962`). The hooks are the same in every framework, so one stylesheet serves all five (`core:302`). Our own token variables can drive all of it.
- **With four of the five adapters, server markup carries state.** With React, Vue, Svelte and Solid, parts render their attributes into the server's HTML (`core:867`). Web components are the exception; see below.
- **It keeps native forms working before its script loads.** A submit button submits and a native input accepts text before the component upgrades. The docs tell authors to include native fallback markup for any control that must submit before then (`web:1042`, `web:1044`).
- **It has a field with a per-field error part.** `ui-field` connects a control to its label, description and error; the error part shows the browser's own message when empty, and a server's message when a script sets it (`web:954`, `web:978`, `web:1017`).
- **It has a test kit.** `checkPattern` checks a component's roles, names, states and keyboard handling against one of fifteen named patterns (`core:7804`, `core:7816`); `checkServer` fails a part that reads browser state while rendering on a server (`core:7896`); and the test harness captures what was announced to a screen reader (`core:7884`). The fifteen patterns include dialog, combobox, listbox and checkbox. They do not include button, field, date picker, calendar, popover or toast.
- **It has helpers our slices need.** Currency and number formatting and parsing (`core:2525`, `core:2558`). Calendar-date arithmetic and month grids (Dates section), a Time Input component (`web:1347`; its page was not read), and time ranges on tracks with snapping and overlap rules, shown as room bookings (`core:5208`, `core:5234`, `core:5277`). Field hints for keyboards and autofill (`core:4131`). A way to lift a bottom bar above the on-screen keyboard (`core:3394`). Screen-reader announcements (`core:3232`). And, for a chat screen, a list that follows new messages without pulling a reader who scrolled up (`core:5757`), recall of earlier messages (`core:2305`) and safe handling of half-typed text in languages that compose characters (`core:2301`).
- **Agents can operate the page, with limits a person sets.** An agent can list the components on a page, act on them and watch changes (`agents:326`, `agents:388`). A control marked `data-agent-confirm`, such as a payment, always needs a person (`agents:950`). The values of password, card and one-time-code fields are redacted from the agent automatically (`agents:989`, `agents:1002`). A change made by an agent is labelled as such and can be undone separately from the person's own edits (`agents:1008`, `agents:1180`). Suggested values can be applied to the real controls and reverted, which fits a proposal card (`agents:1112`).
- **Its docs are packaged for agents.** Each package carries its own `llms.txt` and Markdown docs inside the installed folder (`agents:111`), and `@ui-sdk/core` carries a skill that always matches the installed version (`agents:294`). This is a working example of what our own docs for agents should do.
- **Licence and source.** Apache-2.0, public repository at github.com/vercel-labs/ui *(lead re-checked)*. No package has a runtime dependency *(lead re-checked for core)*.

## Facts that cost us

- **It is a pre-release package, three days old.** The repository was created on 26 October 2026 and `@ui-sdk/core` was first published on 12 November 2026. The published versions are a placeholder (0.0.0-stage) and 0.1.0-beta.1, beta.2 and beta.3, published on 12, 13 and 15 November (UTC); the `latest` tag points at beta.2. The repository shows 107 open issues and pull requests *(all lead re-checked)*. Our charter allows no pre-release dependency in brick (`charter/principles.md`, principle 6; `charter/budget.md`, row 6).
- **It says it may change.** The README places it under Vercel's public beta terms: "the framework, APIs, documentation, and behavior may change before general availability" *(lead re-checked)*. The docs say any export can change between releases and that some are marked experimental (`core:2043`). The agent key for custom components and the history and undo helpers are among the experimental ones (`agents:896`, `agents:1116`).
- **One account controls it on the registry.** The only maintainer listed is one personal account. Beta.1 was published from that account; beta.2 and beta.3 were published by the repository's GitHub Actions workflow with provenance attestations *(reviewer re-checked)*. The repository belongs to a Vercel organisation and security reports go to a Vercel address.
- **Its JavaScript is far above our starting budget.** Measured from the hosted browser files (`raw/2026-11-14-ui-sdk-size.txt`, made by `raw/measure-ui-sdk-size.py`): a button needs about 20 kilobytes compressed, a field 22, a calendar 38, a toast 45, a select 68, a date picker 68. Button, input, label, field and toast together need about 55, with shared files counted once. Our starting budget for enhancement JavaScript is 5 kilobytes per component and 15 for the checkout slice (`charter/budget.md`). An app that bundles the packages may ship less; that has not been measured. On bundling the docs say only that each component is imported from its own entry (Vue file, line 86), and the package declares that only its CSS files have side effects.
- **Its behaviours need JavaScript.** Focus management and positioning are client-only (`core:650`); keyboard navigation and state changes need the component's script (`web:1042`). Our core tasks must work with none.
- **With web components, nothing computes state on the server.** We would write the initial markup and its ARIA state by hand, and the element takes over when its script loads (`core:867`, `web:1038`).
- **An agent can still type into a card field.** A secret field's value is redacted, but the field stays visible to the agent and it can type into it. Keeping a field from the agent entirely needs `data-agent-hidden` (`agents:988`, `agents:989`).
- **Its default stylesheet is not for us.** The optional `web.css` gives every component a default look (`web.md:16`) and measures 12 kilobytes compressed, which is our whole CSS budget for the slice. We would not load it.
- **It injects a small stylesheet of its own.** A cascade layer named `ui-sdk` carries behavioural CSS, and a strict content security policy blocks it unless a nonce is supplied (`web:558`, `web:566`). Its contents were not read.
- **Built-in screen-reader messages default to English** for eleven drag, selection and canvas behaviours; each takes a function to replace them (`core:4472` and ten more).
- **Month grids are Gregorian only.** A locale with different months, such as Persian, gets Gregorian labels; one that shares the months, such as Thai Buddhist, keeps its own years (`core:2752`).
- **The Solid adapter depends on a release candidate of Solid** (`core:8036`).
- **Multi-step agent actions do not roll back** when a later step fails (`agents:406`), and a permission function that returns true without reading the confirmation flag answers yes for the person (`agents:978`).
- **Toast needs a script call** and a host element (`web:715`).

## What the docs do not say

Each of these was looked for by a reader, and a reviewer then searched all ten files for it.

- Any claim of conformance to WCAG at any level.
- Any browser-support statement.
- Any size figure from the project itself.
- Any inline alert, page-level status message or error summary. The feedback parts that exist are the field error part, Progress and Toast.
- Any table, description list or other part that could serve as a cost summary.
- Any chat message, message list or proposal card. Only building blocks exist.
- Any guidance on touch target size, or contrast checking beyond a WCAG 2 ratio helper.
- Any general reduced-motion setting. The scroll wheel jumps instead of gliding under reduced motion (`core:5913`); for CSS transitions the author writes the rule (`core:6299`).
- Any support for design tokens or the Design Tokens Community Group format.
- Any date-and-time value that carries a time zone, or a ready-made appointment-slot picker.
- Any support outside the web.

## What the lead noticed in the docs themselves

- The docs contain prompts addressed to an AI agent: install the packages, edit AGENTS.md, and run a command that installs a skill from the repository. No reader acted on them, and the lead did not. A skill is not installed in this repo unread.
- Their benchmark compares an agent using their bridge with an agent using browser tools: 5 against 16 tool calls, on one task, three runs each, against an unnamed other library (`agents:89`). It is one task and cannot be compared with ours.
- The docs contradict themselves on where a part's role is declared (`core:499` against the rating example in Compose Behaviors).
