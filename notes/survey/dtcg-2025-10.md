# Design Tokens Community Group format, version 2025.10

## Status
- The format page calls itself a "Final Community Group Report" published 28 October 2025, and says it is not a W3C Standard and not on the Standards Track. https://www.designtokens.org/tr/2025.10/format/
- The same page contradicts itself: its status section says it was published as a Candidate Recommendation. The resolver and colour pages show the same conflict. Treat the header ("Final Community Group Report") as the safer reading. https://www.designtokens.org/tr/2025.10/format/ and https://www.designtokens.org/tr/2025.10/resolver/
- The group is a W3C Community Group. Its announcement says "first stable version" and "open standard", but never says W3C Recommendation. https://www.w3.org/community/design-tokens/2025/10/28/design-tokens-specification-reaches-first-stable-version/
- A living draft continues beside the stable version. https://www.designtokens.org/

## Modules
- Format: the file format, tokens, groups, aliases, types and composite types. https://www.designtokens.org/tr/2025.10/format/
- Colour: how colour and opacity are represented. https://www.designtokens.org/tr/2025.10/color/
- Resolver: how sets and modifiers combine into a final token set. https://www.designtokens.org/tr/2025.10/resolver/
- The announcement does not use the word "modules"; the three-way split comes from the three spec pages. https://www.w3.org/community/design-tokens/2025/10/28/design-tokens-specification-reaches-first-stable-version/

## Syntax (format module)
- Token: an object with `$value`; its parent key is its name. Names cannot start with `$` or contain `{`, `}` or `.`, and are case-sensitive. https://www.designtokens.org/tr/2025.10/format/
- `$type`: optional on a token or group, inherited from the nearest parent group. If no type can be determined the token is invalid; tools must not guess from the value. Same source.
- `$description`: optional plain string. Same source.
- Aliases: curly-brace form `{group.token}` points at a whole token. JSON Pointer form uses `$ref` (RFC 6901) and can point at any location, including part of a value, for example `#/colors/blue/$value/components/0`. Circular references are errors. Same source.
- Groups: an object without `$value`. An object with both `$value` and child tokens is invalid. Group properties are `$description`, `$type`, `$extends`, `$deprecated`, `$extensions`. `$root` is a reserved name for a group's base token. Same source.
- `$extends`: points at a group, deep-merges, and local definitions replace inherited ones. Same source.
- Composite types: object or array values whose parts may be literal values or references of the right type. Same source.
- Dimension: `$type` `dimension`; `$value` is an object with numeric `value` and `unit`, where unit is `"px"` or `"rem"` and is required even at 0. Same source.
- Colour object: `$type` `color`; `$value` has required `colorSpace` and `components`, optional `alpha` (0 to 1, default 1) and `hex` (6-digit fallback). Components are numbers or the keyword `none` ("not applicable or not specified"); the page says a hue of `none` MAY be rendered differently from a hue of 0. Fourteen spaces are listed, including sRGB, Display P3, HSL, OKLAB and OKLCH. https://www.designtokens.org/tr/2025.10/color/

## Themes and modes (resolver module)
- A `.resolver.json` file has required `version` ("2025.10") and `resolutionOrder`, plus `sets` and `modifiers`. https://www.designtokens.org/tr/2025.10/resolver/
- A set is a list of `sources` (inline tokens or `$ref` files); a later duplicate wins. Same source.
- A modifier holds named `contexts`, each a list of sources, with an optional `default`. A theme or mode is a modifier; light and dark are its contexts. Same source.
- `resolutionOrder` lists sets and modifiers; later items override earlier ones. The caller picks contexts with an input such as `{ "theme": "dark" }`. Same source.
- Resolver examples 14 and 17 write `context` where the normative syntax says `contexts`. Bundling with `$defs` is undefined. Same source.

## Stable versus draft
- The format and colour pages say the specification is stable. The announcement presents all of 2025.10 as stable. https://www.designtokens.org/tr/2025.10/format/ and https://www.w3.org/community/design-tokens/2025/10/28/design-tokens-specification-reaches-first-stable-version/
- Still open in the format page: a JSON Schema is being explored; font family, stroke style, border and transition carry feedback or complexity notes; section 8.8 "Additional types" is non-normative. https://www.designtokens.org/tr/2025.10/format/

## Tool support
- Style Dictionary: latest release seen is v5.8.0 (3 Nov; the page shows no year). v5.7.0 added DTCG 2025.10 `duration` values. The releases page mentions no resolver, colour-object or dimension-object support. https://github.com/style-dictionary/style-dictionary/releases
- Style Dictionary's own docs say 2025.10 "does not have full support yet" and that full support is work in progress for v5. https://styledictionary.com/info/dtcg/
- Terrazzo: its docs say resolver and other 2025.10 features are planned for 2.0; today its `bundle` command can merge a resolver's files into one JSON file. The same page also claims Terrazzo "is the only tool that supports the full DTCG format" compared with Style Dictionary; given the 2.0 note, read this as not covering 2025.10. https://terrazzo.app/docs/
- Tokens Studio: named a reference implementation by the group, alongside Style Dictionary and Terrazzo (the announcement names all three; being named does not mean full 2025.10 support, see above). https://www.w3.org/community/design-tokens/2025/10/28/design-tokens-specification-reaches-first-stable-version/ Its settings docs offer a legacy format or a W3C DTCG format, with more DTCG types to come (not verified on the page itself; from a search summary of https://docs.tokens.studio/manage-settings/token-format). Whether its export targets 2025.10 or an earlier draft: could not find.
- The announcement says "more than 10 design tools and open-source projects" support or are implementing the format, and names seven: Penpot, Figma, Sketch, Framer, Knapsack, Supernova and zeroheight. What each supports was not checked. https://www.w3.org/community/design-tokens/2025/10/28/design-tokens-specification-reaches-first-stable-version/

## For Souvenir
- Learn from the shape: a theme or mode is a resolver modifier, and light and dark are its contexts.
- Do not call it a W3C standard. Say "Community Group report, declared stable".
- Before claiming 2025.10 conformance, check token files against the colour object (`colorSpace`, `components`) and the dimension object (`value`, `unit`).
- Do not rely on the resolver in Style Dictionary or Terrazzo yet; both say support is incomplete. Plan to resolve themes in our own build step.
- Treat any tool's "supports DTCG" as unproven until tested against a 2025.10 sample file.
