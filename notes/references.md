# References

Study these for principles and methods. Copy no one's visual style. Check each is current before relying on it.

## Process sources (read in the setup step, summarise into notes/sources/)
- FigJam board, the agreed process model: https://www.figma.com/board/Thy6ULSqteAMzw9o65a9Te/Design-system-research?node-id=147-115 (the "Souvenir / a living design system" section and the "Proposal model" section below it). Read-only.

- Systems Notebook (Dubberly course notes): https://claude.ai/artifact/J5p1AfSkqVkVqpzPeH4Nj2

## Design systems to study
- Shopify Polaris: closest to the beachhead; built for commerce, strong content guidelines.
- GOV.UK Design System: accessibility, plain language, evidence-based contribution rules.
- Material Design 3: thorough systematisation of elevation, motion and colour roles.
- IBM Carbon: open governance, versioning and documentation at scale.
- Atlassian Design System: structured content served to AI agents.
- Apple Human Interface Guidelines: short, opinionated principles that steer decisions.

## GitHub repos and specs
- Design Tokens Community Group spec 2025.10: the token format.
- Style Dictionary: one token source to every platform's format.
- Radix UI and React Aria: accessible, unstyled component behaviour.
- UI SDK (github.com/vercel-labs/ui): headless behaviours with React, Vue, Svelte, Solid and Web Components adapters. In beta; record the risk.
- shadcn/ui: distribution through a CLI that agents handle well.
- Storybook: component isolation and the base for visual and accessibility tests.
- github.com/kylezantos/design-motion-principles: motion principles.
