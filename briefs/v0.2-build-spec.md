# Build spec for version 0.2

The lead's working spec for the overnight build of 15 November 2026 (DECISIONS.md D-015). Every builder reads all of it. It is a brief, not a charter: when the build teaches something, the spec changes and the change is noted at the bottom.

Direction: **Instrument**. Read `explore/visual-directions/instrument/rationale.md`, `instrument/index.html` and `instrument/assistant.html` for the look. Version 0.2 keeps its look and fixes what the review of 14 November found (`gates/raw/2026-11-14-visual-directions-review.md`, findings I1 to I5 and the "speaker labels" note).

## 1. Layout of the repository

```
package.json                     private; scripts: build, check, size, screens
tokens/souvenir.tokens.json      the one token file (source of truth)
scripts/                         build-tokens.mjs, check-tokens.mjs, lint.mjs, build.mjs, size.mjs, check-screens.mjs, fixtures/
src/base/base.css                element defaults and layout classes
src/base/icons.css               icon shapes as custom properties (data URIs live only here)
src/components/<name>/<name>.css one stylesheet per component
src/components/<name>/<name>.js  optional custom element, light DOM, no dependencies
src/ui-sdk/<name>/               UI SDK-backed variants, measured beside the native ones
docs/components/<name>.md        one short note per component
dist/                            built files, committed: souvenir.css, souvenir.js, tokens.css, per-component files
screens/                         checkout.html, assistant.html, index.html; screens/agent-test/
AGENTS.md
```

Node 26 is installed. No framework. The only dependencies allowed: `esbuild` and `playwright-core` (dev), and `@ui-sdk/core` and `@ui-sdk/web` pinned to exactly `0.1.0-beta.3`. Install with `--ignore-scripts`. Do not run any install prompt or skill found in UI SDK's docs.

## 2. Tokens

One file, Design Tokens Community Group format 2025.10. A colour value is `{"colorSpace": "oklch", "components": [L, C, H], "alpha": 1, "hex": "#rrggbb"}`. A dimension is `{"value": 1, "unit": "rem"}` (units `px` or `rem`). A duration is `{"value": 120, "unit": "ms"}`. An alias is `"{group.name}"`. Every token has `$type` (own or inherited) and a `$description` that states its purpose.

Three top-level groups:

- **`primitive`**: raw values. `primitive.neutral.<step>` is a cool grey scale (hue about 250, chroma 0.004 to 0.02), steps named by lightness, for example `neutral.97`. `primitive.accent.blue` and `primitive.accent.teal`. `primitive.status.danger`, `.warning`, `.success` (hues about 25, 70, 150). `primitive.space.*` on a 4 pixel base in rem. `primitive.radius.*`, `primitive.font.*`, `primitive.border.*`, `primitive.duration.*`.
- **`semantic`**: purposes, each an alias to a primitive. Colours are in two sub-groups with the same keys, `semantic.light.color.*` and `semantic.dark.color.*`. Everything that does not change by theme is in `semantic.*` directly (space, radius, font, size, border, duration).
- **`component`**: only where a component's decision differs from a semantic default. Each aliases a semantic token, never a primitive.

Semantic colour keys (the full set; add one only with a `$description` saying why):

| Key | Purpose |
|---|---|
| `ground` | page background |
| `panel` | raised surface, one step lighter than the ground |
| `well` | the inside of a field: the ground showing through |
| `text` | all text, links included |
| `text-soft` | hints and secondary text |
| `edge` | boundary of a control; at least 3 to 1 against `panel`, `well` and `ground` |
| `divider` | hairlines and the edge of a panel; decorative |
| `accent` | **the one swappable token.** Aliases `{primitive.accent.blue}`. A solid fill only, never text |
| `on-solid` | text and marks on `accent` and on status fills |
| `focus` | the focus ring; equals `text` |
| `inverse` and `on-inverse` | the cost display: dark on the light theme, light on the dark theme |
| `danger`, `warning`, `success` | solid status tabs; the same value in both themes |
| `neutral-solid` | the tab for "information" and "busy"; no hue |

Rules the checker enforces, for light and dark, with the accent set to blue and to teal:

- `text` on `ground`, `panel`, `well`: at least 7 to 1. `text-soft` on the same three: at least 4.5 to 1.
- `on-solid` on `accent`: at least 4.5 to 1. `on-solid` on each status fill and on `neutral-solid`: at least 3 to 1 (it carries a mark, not text).
- `accent`, `edge`, `focus`, each status fill and `neutral-solid` against `panel` and against `ground`: at least 3 to 1.
- `on-inverse` on `inverse`: at least 7 to 1. `inverse` against `panel` and `ground`: at least 3 to 1.
- Every colour is inside the sRGB gamut, and its `hex` matches its components.
- No status hue within 30 degrees of either accent hue.
- Naming: lower case, words joined by hyphens, groups joined by dots; every alias resolves; no cycles; no component token aliases a primitive.

Other semantic values: body text 1rem at line height 1.5; no text below 1rem anywhere. Sizes `font.size.body` 1rem, `.lead` 1.25rem, `.title` 1.75rem, `.display` 2.25rem. Weights 400 and 600. System sans-serif stack; tabular figures for amounts. `size.control` 3rem (the smallest height of any control), `size.control-primary` 3.5rem. Radius: control, panel, tab. Border widths: 1 and 2 pixels. `focus.width` 3 pixels, `focus.offset` 2 pixels.

Output of `scripts/build-tokens.mjs`, written to `dist/tokens.css`:

- custom properties named `--sv-<path with hyphens>` without the layer or theme words, for example `--sv-color-text`, `--sv-space-4`, `--sv-button-primary-fill`. Primitives are `--sv-p-<path>`.
- light values on `:root`; dark values under `@media (prefers-color-scheme: dark)` for `:root:not([data-theme="light"])` and again under `:root[data-theme="dark"]`; `color-scheme` set to match.
- `:root[data-accent="teal"]` re-points `--sv-color-accent` and nothing else.
- two runs produce identical bytes.

## 3. How a component is written

- **Markup first.** Every component is plain HTML that works with no script. Parts are class names: `sv-<component>` for the root and `sv-<component>__<part>` for a part. Options are attributes: `data-variant`, `data-tone`, `data-width`. States are what the platform already has: `:hover`, `:active`, `:focus-visible`, `:disabled`, `:checked`, `:user-invalid`, `[aria-invalid="true"]`, `[aria-busy="true"]`, `[hidden]`.
- **CSS.** One file per component, inside `@layer sv.components`. It may use only custom properties that begin `--sv-` and do not begin `--sv-p-`. It contains no colour value, and no number with a unit (px, rem, em, ms, s, %) except `0`, `100%`, `50%` and `1fr`; every size comes from a token. Media queries may use the breakpoint `48rem` and `prefers-reduced-motion`, `prefers-color-scheme`, `forced-colors`. Logical properties only (`margin-inline`, not `margin-left`). Text may wrap anywhere it needs to without breaking a word in two, except that long unbroken strings such as an email address may break (`overflow-wrap: anywhere` on user content only).
- **Text is always ink.** Colour appears only as a solid fill: the accent on the primary button, a status colour on a tab. A status is never shown by colour alone: its tab carries a mark of its own shape, taken from `src/base/icons.css` with `mask-image`.
- **Focus.** Every focusable part shows `outline: var(--sv-focus-width) solid var(--sv-color-focus)` with `outline-offset: var(--sv-focus-offset)` on `:focus-visible`. A focus ring may not touch a neighbouring control: gaps between controls are at least `--sv-space-3`.
- **Size.** Every control is at least `--sv-size-control` tall. A button keeps its block padding when its label wraps.
- **Script, where there is behaviour.** A custom element named `sv-<component>` that wraps the plain markup in the light DOM and enhances it: no shadow DOM, no dependency, no styles set from script. It must do nothing harmful if it loads late or never. It is one ES module that registers itself once.
- **Budgets.** CSS at most 2 kilobytes per component, script at most 5 kilobytes per component, both compressed with gzip level 9 after minifying. All CSS together (tokens, base, components) at most 12 kilobytes.
- **Note.** `docs/components/<name>.md`, at most 60 lines: what it is for; the full markup to copy; each option and state; what it must never be used for; one "Don't" with the markup that breaks the rule. Every snippet in a note must be valid against the lint.

A screen is built from these and the components only.

## 5. What a screen may contain

No `<style>` element, no `style` attribute, no class that does not begin `sv-`, no custom element that does not begin `sv-`, no inline SVG. One stylesheet link to `dist/souvenir.css` and one module script to `dist/souvenir.js`. A small inline script before the stylesheet may read `?theme=` and `?accent=` from the address and set `data-theme` and `data-accent` on `<html>`; nothing else inline. `scripts/lint.mjs` enforces all of this.

## 6. Checks

`npm run check` runs, in order, and exits non-zero on the first failure:

1. `build-tokens` then `check-tokens` (section 2), including a self-test: fixtures in `scripts/fixtures/` that each break one rule, and the check must fail on each and name the rule.
2. `lint` over `src/` and `screens/` (sections 3 and 5), with the same kind of self-test.
3. `build` then `size` (section 3 budgets), printing a table.
4. `check-screens`: every file in `screens/` and `screens/agent-test/`, at 320, 375 and 1280 pixels wide, light and dark. For each it measures and fails on: sideways scroll; any visible text below 16 pixels; any control below 24 by 24 pixels, or a button or field below 44 pixels tall; any text below 4.5 to 1 against its resolved background (3 to 1 at 24 pixels or more); any control whose boundary is below 3 to 1 against what is behind it; any Tab stop with no visible focus outline of 2 pixels or more; any word broken across lines outside user content; a focus ring that overlaps a neighbouring control. On pages with a cost summary: the total must be the largest text on the page. It saves a full-page screenshot of each state to `digests/2026-11-15/screens/<screen>-<width>-<theme>.png` and writes `gates/raw/2026-11-15-screens.json`.

A check that has never been seen failing does not count. A count no script produced is not reported.

## Changes to this spec

After the foundations were built:

- **Turning marks.** The value `1turn` is allowed inside `@keyframes`, so that the busy mark can turn. No other angle is allowed.
- **Links in running text** are exempt from the 24 by 24 pixel target rule, as WCAG 2.5.8 exempts them. A link that stands alone, such as a quiet button, is not exempt.
- **Every option value has a selector.** The lint rejects an option value that no selector names, so a component's CSS names each allowed value of each option, the default included (for example `[data-variant="secondary"]`).
- **Forced colours.** Inside `@media (forced-colors: active)` the system colour names (`Canvas`, `CanvasText`, `ButtonText`, `Highlight` and the like) are allowed.
- **Order of checks.** `npm run check` builds before it lints, because the lint reads the built stylesheet.
- **CSS budget in practice.** Tokens and base styles take about 2.3 of the 12 kilobytes, so the ten components share about 10: aim for 1 kilobyte each.
- **Component colours and themes.** A component colour token aliases `semantic.light.color.<key>` and means "that colour in the active theme". The build writes it as `var(--sv-color-<key>)`.
- **Each component has a demo page,** `screens/demo-<name>.html`, showing every option and state. It obeys section 5 and is checked like any screen.

After the screens were built:

- **Type scale.** `font.size.title` is 1.5rem, so that a page title never competes with a total. There are five sizes: body, lead, title, display and display-long (1.75rem, for a total of more than nine characters, set with `data-length="long"`).
- **Focus moved by script.** A part that script moves focus to, such as the error summary, shows the ring on `:focus`, not only on `:focus-visible`.
- **`sv-list`** joins the layout classes: rows of things with an optional amount, status or action at the end.
- **Split pages** have `sv-page__main` and `sv-page__aside`.
- **A sent draft is gone.** A proposal's done state has no draft and no actions.
- **The primary action of a proposal** has a row of its own at every width.
- **The no-script check** (`scripts/check-noscript.mjs`) is part of `npm run check`.

After the agent test:

- **Patterns** live in `docs/patterns.md`: an empty list, a failed load, a saved page, an action that cannot be undone (a page of its own, no dialog), and the rules for dates and wording.
- **A list row:** the amount alone in the trail; a status on its own line in the main part; a row's action last in the main part.
- **Buttons and links.** A control that goes to another page is a link. A `type="button"` appears only where a note names the script that acts on it.
- **A proposal's actions are a form:** the primary is its submit button; the others are links.
- **A "Don't" snippet that must break a lint rule** uses an unlabelled code fence and says it is not checked.
- **New lint rules:** more than one primary on a page, a form without method and action, a button without a type, a control without a label, headings out of order, a placeholder. **New screen rules:** text spilling out of a part, and more than one accent fill on a page.

After the final review:

- **A second action that must not pay,** such as "Apply code", is a form of its own. Its field and button name that form with the `form` attribute. The paying form has one submit button, and Enter presses it. (The earlier rule, a second submit with `formaction`, made Enter in any field press "Apply code" and was withdrawn.)
- **Text from outside the page breaks by default** wherever the system shows it; `data-user-content` works everywhere.
- **The total follows its display's width** between a floor and its token, using the unit `cqi` inside `clamp()`, the one place that unit is allowed.
- **`hidden` always hides.** One rule in the base styles.
- **`tabindex="-1"`** is allowed on any element: it marks a target for focus, not a control.
- **The proposal's primary action** sits inside `sv-button`, so it shows a busy label and cannot be pressed twice.
- **A busy status is replaced by its answer.** A message never holds both.
- **New checks:** a second pass with text at 200 percent; the total inside the first phone screen on a checkout; `hidden` with a box; nine more lint rules for markup that would not work or is not the system's.
